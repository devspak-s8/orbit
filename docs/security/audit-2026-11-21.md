# Security Audit — 2026-11-21

Full-surface audit of the ORBIT API after v1.0.0. Method: systematic source
sweep of every registered route (80 routes across 9 services) cross-checked
against membership/role enforcement, plus a live end-to-end attack suite
(`server/internal/httpapi/security_audit_test.go`) executed against a running
API with two users, two workspaces, all modules enabled, and an API token.

The live suite covers 11 categories: auth bypass, tenant isolation (full
route inventory), SQL injection, token forgery, MCP auth, webhook no-leak,
payload limits, delete protection, Bearer lifecycle, cookie flags, and
member-vs-owner role checks. It skips when no API is running, so the offline
suite is unaffected.

## Findings and fixes

All five findings were fixed in the same pass and verified live.

### 1. Module listing leaked to any authenticated user (HIGH — fixed)

`GET /v1/workspaces/{id}/modules` checked authentication only. Any logged-in
user could enumerate any workspace's installed modules and enabled state.

*Fix:* membership check in `handleAvailable` via `requireMemberForRead`
(`modules/http.go`), uniform 404 for strangers.

### 2. Event log leaked to any authenticated user (HIGH — fixed)

`GET /v1/workspaces/{id}/events` had a comment claiming "the workspace
membership guard runs in the router" — it didn't. The router applies only
`RequireUser` (authentication). Any logged-in user could read any workspace's
full event history, which includes task/record/page payload data.

*Fix:* `requireMember` added to the events service and enforced in the
handler (`events/events.go`), uniform 404 for strangers.

### 3. Demo module read/write without membership (HIGH — fixed)

The demo gate checked authentication and module-enabled status but never
membership. Any logged-in user could list and **create** records in any
workspace with the demo module enabled.

*Fix:* `requireMember` in the demo service, enforced in the gate before the
module-status check (`demo/http.go`, `demo/service.go`).

### 4. Module-status probe leak in gates (LOW — fixed)

The work/data/docs gates checked module status before membership. A stranger
probing a workspace UUID received "module disabled" when the workspace
existed but the module was off, vs "forbidden" when it existed with the
module on — distinguishable responses confirmed the workspace's existence
and module state.

*Fix:* all three gates now check membership first and return a uniform 404
("not found") for strangers; only members see the module-off state
(`work/http.go`, `data/http.go`, `docs/http.go`).

### 5. Validation before authorization in workflow create (LOW — fixed)

`automation.Service.Create` validated the workflow definition before
checking membership, so authorization ordering violated policy (validate
after authorize). Reordered: `requireMember` now runs first.

## Hardening added

* `ORBIT_COOKIE_SECURE=true` env var sets the `Secure` flag on session
  cookies — required for the public demo deployment behind TLS. Defaults off
  for local HTTP development. Cookies already carried `HttpOnly` and
  `SameSite=Lax`; both flags are now asserted by the audit suite.

## Verified sound (no action needed)

| Surface | Result |
|---|---|
| Auth bypass | 17 protected routes all return 401 without credentials |
| Tenant isolation | Full route inventory: strangers get 403/404, never 200 |
| SQL injection | All queries parameterized; payloads stored as literal text, DB stays healthy |
| Token forgery | SHA-256-at-rest Bearer lookup rejects forged/malformed tokens |
| MCP endpoint | Bearer-only, delegates to the same token path; 401 without/forged credentials |
| Webhooks | IP rate limit, 1 MB cap, uniform 404 (no existence leak) |
| Public forms | IP rate limit, 1 MB cap, uniform 404 |
| Payload limits | `http.MaxBytesReader` (1 MB) on every body decode; 2 MB register body rejected |
| CORS | Strict origin allowlist, `Vary: Origin`, no wildcard |
| Cookie flags | `HttpOnly` + `SameSite=Lax` asserted; `Secure` configurable |
| Workspace delete | Owner-only + exact-name confirmation; verified non-owner and wrong-name rejections |
| Invites | Owner-only creation (uniform 403 for strangers/members), expiry enforced (unit-tested) |
| Sessions | Argon2id password hashing, revocable, TTL-bound |
| Rate limits | Auth 10/min per IP, webhooks and forms limited independently |
| Agents | All queries user-scoped; token ownership enforced |
| Owner actions | Module lifecycle, invites, rename, delete: member role gets 403 |

## How to re-run

```
# Terminal 1 — API up
cd server && go run ./cmd/api

# Terminal 2 — live audit (fresh, never cached)
go test -p 1 -count=1 ./internal/httpapi/ -run TestSecurityAudit -v
```

The audit mutates its own workspaces and users; it is safe to run against a
dev instance at any time. Future routes should be added to the inventory in
section 2 as they are registered.
