> **Status: shipped in v1.2.0.** Verified: six new backend tests, the full
> offline suite, a live end-to-end pass (eval dry-runs with zero deliveries,

Three features in one release: quality infrastructure for the automation
engine (evals), operational self-healing (failure notifications + retry),
and ORBIT on the desktop (Electron).

## 1. Workflow evals

Replay payloads as **dry-runs** with assertions. The engine simulates a
definition against a payload — no HTTP calls, no emails, no queue — and
records what each node *would* do. Assertions verify the dry-run.

**Why dry-run (not real execution):** evals must be safe to run against
live workflows — an eval that posts to your Slack channel every time would
be worse than no evals.

**Simulator** (`simulate.go`): mirrors the runner's graph walk (branch
routing, skipped paths, cycle safety) with intercepted nodes:
- http → `SimRequest{method, url, headers, body}` after connector
  expansion and `{{payload.*}}` substitution — never sent
- email → `SimEmail{to, subject, text}` — never sent
- branch → evaluates the condition (pure) → `taken`
- log → substituted message

**Assertions** (stored JSONB, `[]Assertion{nodeId, property, op, value}`):
- properties: `status`, `taken`, `message`, `request.url`, `request.method`,
  `request.body.<key>`, `email.to`, `email.subject`
- ops: `==`, `!=`, `contains` (string substring)

**API** (workspace-scoped, member-gated like all workflow routes):
- `POST   /workspaces/{id}/workflows/{wid}/evals` — create {name, payload, assertions}
- `GET    /workspaces/{id}/workflows/{wid}/evals` — list with latest result
- `POST   /workspaces/{id}/workflows/{wid}/evals/{eid}/run` — simulate + assert + persist
- `POST   /workspaces/{id}/workflows/{wid}/evals/from-run/{rid}` — seed from a
  recorded run's trigger payload ("replay recorded payloads")
- `DELETE /workspaces/{id}/workflows/{wid}/evals/{eid}`

**Migration 00013:** `workflow_evals` + `workflow_eval_runs` (results history,
latest shown in lists).

**UI:** Evals section on the workflow page — create (name/payload/assertions
JSON), create-from-run button on each run row, run button, pass/fail with
per-assertion detail.

## 2. Self-healing notifications

- **Failure notifications:** when a run fails, every workspace member gets an
  in-app notification (type `workflow.failed`) with the workflow name, error,
  and run ID. Inserted after the run status update; notification failures
  are logged, never fail the run.
- **Anomaly escalation:** when the workflow's last 3 runs all failed, the
  notification carries `anomaly: true` and escalates the wording — repeated
  failures should be loud, once-failures should be quiet.
- **One-click retry:** `POST /workspaces/{id}/workflows/{wid}/runs/{rid}/retry`
  — enqueues a fresh run with the failed run's trigger payload (failed or
  cancelled runs only; draft workflows still refuse to run). UI: Retry
  button on failed/cancelled runs.

## 3. Desktop app — Electron

The user chose Electron explicitly (Tauri rejected). The desktop app is a
shell for *any* self-hosted ORBIT instance:

- `apps/desktop/` — Electron main process, preload bridge, connect screen
- First run: enter the server URL → main process validates `/healthz` →
  saved to `userData/settings.json`
- Window loads the ORBIT web app; tray icon (open, change server, quit);
  basic native menu; settings stored as plain JSON (no extra deps)
- Packaged with electron-builder (Windows NSIS installer for v1.2.0,
  mac/linux targets configured for later); a programmatic PNG icon
  (generated with a small Go script — no design toolchain dependency)

  skipped paths) + assertion evaluator tests
- Eval e2e: create eval from a recorded run → run → assert on the dry-run
  request
- Failure-notification + anomaly-escalation + retry e2e (fail a workflow
  deliberately, check member notification rows, retry it)
- Live API pass + browser pass for both web features; desktop app launched
  and connected to the dev stack on this machine

## Non-goals (deferred)

- Eval scheduling/CI modes (run all evals on definition change)
- Notification channels beyond in-app (email digest of failures)
- Auto-retry policies (exponential backoff, N attempts then stop)
- Desktop: bundled local server (single-user mode), OS notifications,
  auto-update
